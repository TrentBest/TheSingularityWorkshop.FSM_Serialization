# Data Models and UML Data Cards

Document the shapes that cross a boundary: fields/properties, type and nullability, ownership/lifetime, invariants, encoding/representation, transformation steps, and failure conditions.

A UML data card has a colored border and a clear header; clicking it expands nested content. Keep a concise summary visible and place details inside the expandable body. Link each field and relationship to its source declaration where possible.

Do not confuse a type diagram with a serialized wire format. The data model must explicitly identify which facts are source declarations, domain rules, or format-specific encoding rules.
